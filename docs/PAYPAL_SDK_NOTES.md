# PayPal Python Server SDK: notes

Package: **`paypal-server-sdk` 2.4.0** (generated by APIMatic; import name `paypalserversdk`).

**Source:** I read these straight from the installed package (`.venv/Lib/site-packages/paypalserversdk`)
on 2026-11-10. This package is the one we use (DECISIONS D-011). The APIMatic Context Plugin documents
a different SDK, so it's used for reference only (D-003). **Check this file before writing SDK calls.**

**The SDK is synchronous** (built on `requests`). From FastAPI, every call runs through `asyncio.to_thread`
(see `SdkPayPal._sdk` in `app/integrations/paypal_sdk.py`). We parse `ApiResponse.text` as JSON and map it with
`paypal_types.subscription_view` / `plan_view`, so the model classes' `APIHelper.SKIP` defaults never leak out.
Request bodies can be plain dicts (`APIHelper.json_serialize` handles dicts and lists).
Client retries: `max_retries` defaults to 0 and applies only to GET/PUT. We set 2.

## Client and OAuth

```python
from paypalserversdk.paypal_serversdk_client import PaypalServersdkClient
from paypalserversdk.configuration import Environment
from paypalserversdk.http.auth.o_auth_2 import ClientCredentialsAuthCredentials

client = PaypalServersdkClient(
    client_credentials_auth_credentials=ClientCredentialsAuthCredentials(
        o_auth_client_id=CLIENT_ID,
        o_auth_client_secret=CLIENT_SECRET,
        # optional: o_auth_token, o_auth_token_provider, o_auth_on_token_update, o_auth_clock_skew
    ),
    environment=Environment.SANDBOX,       # base URL https://api-m.sandbox.paypal.com
    logging_configuration=None,            # LoggingConfiguration / RequestLoggingConfiguration available
)
subs = client.subscriptions                # SubscriptionsController
```

- The OAuth2 client-credentials token is fetched and cached by the SDK, which refreshes it when it
  expires (`o_auth_clock_skew`). On a 401 we still drop the cached token and retry once (spec 7.1).
- `Environment` has only `PRODUCTION` and `SANDBOX`. We always pass `SANDBOX`, and our own startup
  check enforces `PAYPAL_API_BASE == https://api-m.sandbox.paypal.com`.
- `PaypalServersdkClient.from_environment(...)` exists, but we build it from our own config.

## Calling convention

Every controller method takes **one `options: dict`** and returns an `ApiResponse`:
`.status_code`, `.headers` (dict), `.text` (raw body), `.body` (deserialised model), `.is_success()`, `.is_error()`.

## Models (`paypalserversdk.models.*`)

- `PlanRequest(product_id, name, billing_cycles, payment_preferences, status="ACTIVE", description, taxes, quantity_supported=False)`
- `BillingCycle(tenure_type, pricing_scheme, total_cycles=1, sequence=1, frequency)`. Use `total_cycles=0` for unlimited.
- `TenureType`: `REGULAR`, `TRIAL`
- `PricingScheme(pricing_model=None, price: Money)`
- `Money(currency_code, value)`. `value` is a **string**, which maps cleanly onto our `Decimal`-as-string storage.
- `Frequency(interval_unit, interval_count=1)`; `IntervalUnit`: `DAY`, `WEEK`, `MONTH`, `YEAR`
- `PaymentPreferences` (needed by `PlanRequest`): `auto_bill_outstanding`, `setup_fee`, `setup_fee_failure_action`, `payment_failure_threshold`
- `UpdatePricingSchemesRequest(pricing_schemes=[UpdatePricingScheme(billing_cycle_sequence, pricing_scheme)])`
- `CancelSubscriptionRequest(reason)`
- `CreateSubscriptionRequest(plan_id, start_time, quantity, subscriber, auto_renewal=False, application_context, custom_id, plan)`
- `Subscription`: `id`, `plan_id`, `status`, `status_change_note`, `status_update_time`, `billing_info`, `start_time`, `create_time`, `update_time`, `custom_id`, `subscriber`, `links`
- `SubscriptionStatus`: `APPROVAL_PENDING`, `APPROVED`, `ACTIVE`, `SUSPENDED`, `CANCELLED`, `EXPIRED`

## Errors

- `paypalserversdk.exceptions.subscription_error_exception.SubscriptionErrorException(ApiException)`
  is raised for 400/401/403/404/422/500/default on subscription endpoints. Fields:
  `name`, `message`, `debug_id`, `information_link`, `details: list[ErrorDetails]`
  (`field`, `value`, `location`, `issue`, `description`), `links`, plus `response_code`
  and `response` (raw response) from `ApiException`.
- Map these to our typed `PayPalError(name, debug_id, issues=[d.issue ...], status)`.

## Gaps: where we use httpx directly (`app/integrations/paypal_rest.py`, DECISIONS D-010)

1. **Catalog Products** (`POST /v1/catalogs/products`): no controller in this SDK. Needed by `seed_sandbox.py`.
2. **`PayPal-Request-Id` on cancel / update-pricing**: the SDK only exposes that header on the
   create endpoints. Cancel is idempotent on PayPal's side anyway (a repeat gives 422
   `SUBSCRIPTION_STATUS_INVALID`, which we treat as success if the status is now `CANCELLED`).
   To keep the spec's "every POST sends PayPal-Request-Id", these POSTs go through httpx.
3. **`PayPal-Auth-Assertion`** (partner mode): the SDK has no per-call custom headers -> httpx.
4. **`/v1/notifications/verify-webhook-signature`**: not in the SDK -> httpx.
